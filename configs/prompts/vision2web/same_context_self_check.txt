Before submitting, perform a focused, evidence-based self-check using only the public task requirements, PRD, prototypes, resources, and your current implementation. Start or reuse the application at http://localhost:3000. If it is not reachable, launch /workspace/start.sh in the background with Bash or the terminal, wait until the URL responds, and inspect the launch log if it does not. Use the available browser interface to inspect the rendered initial state; curl or raw HTML inspection may confirm reachability but does not count as a visual check. Form a concise checklist of high-value functional objectives, but do not inspect the whole site at once. At each verification step, choose one coherent functional objective, state its observable expectation, and interact step by step with the native browser tools. Use browser_get_state before every indexed click or type action and request include_screenshot=true whenever visual evidence is needed. Inspect the resulting visual and runtime evidence before deciding whether to repair it, recheck it after a meaningful change, move to another objective, or submit. Successful command execution alone is not evidence that the objective holds. You decide which objectives are useful and when the implementation is ready to submit.
